new-delegate

A portable, DeleGate-compatible application gateway written in Go — fail-closed policy, protocol translation, and a differential compatibility harness against the original.

GitHub repo · Full compatibility ledger · Design doc

What it is

new-delegate reimplements the strongest ideas from the original DeleGate application gateway as a single, portable Go binary: a daemon presents one protocol on its client side, maps virtual resources with MOUNT, applies fail-closed access policy, and reaches a different protocol on its server side. Protocol translation is built around typed semantic operations (Fetch, Store, Connect) rather than a bag of protocol-specific optional fields, so new frontends and backends compose instead of special-casing each other.

Fail-closed by default

No matching mount or permit rule denies the request. Unknown configuration keys and directives are fatal, not ignored.

Legacy-compatible, TOML-native

Original SERVER/MOUNT/PERMIT/REJECT directives parse onto the same canonical model as strict, validated TOML.

Reproducible, self-contained releases

Checksummed archives for Darwin/arm64 and Linux/amd64; the same source/version pair always produces the same SHA-256 manifest.

Try it now

Everything below runs from a checkout with just go installed — no external services required.

  1. 1 · Validate a legacy directive line without opening a socket
    go run ./cmd/delegate check \
  SERVER=http -P8080 \
  'MOUNT=/* http://127.0.0.1:9000/*' \
  'PERMIT=http:127.0.0.1:*'
  2. 2 · Run the same thing as strict, canonical TOML
    go run ./cmd/delegate check --config examples/delegate.toml
go run ./cmd/delegate serve --config examples/delegate.toml

    Unknown keys and invalid values are fatal before the listener starts — no silent misconfiguration.

  3. 3 · Ask the gateway what it would do, without a live listener
    go run ./cmd/delegate explain --config examples/delegate.toml \
  --path /some/path --source 127.0.0.1 --method GET

    Returns JSON distinguishing permitted, rejected, no-mount, unsafe-path, and ambiguous-mount outcomes.

  4. 4 · Run the full test suite, including race detection and the compatibility harness
    go test ./...
go test -race ./...
go vet ./...

Architecture

Every request takes the same typed path, regardless of frontend or backend protocol:

connection→ frontend server→ protocol decoder→ typed wire message→ semantic operation→ mount resolver→ policy engine→ backend connector→ semantic result→ protocol encoder→ connection

Transparent forwarding (CONNECT relays) uses a byte-stream path after routing and policy approval — it never manufactures a semantic operation for traffic it isn't inspecting.

Stable module boundaries

config

Canonical configuration plus TOML and legacy syntax adapters.

server

Listener lifecycle, limits, deadlines, connection context.

protocol

Typed frontend and backend wire codecs.

operation

Protocol-neutral capabilities: Fetch, Store, List, SendMail, Connect, Relay.

mount

Deterministic mapping from frontend names to backend targets.

policy

Explicit permit/reject decisions with default deny.

tlsconfig / tlsruntime

Side-effect-free TLS policy, then explicit certificate loading.

connector

Backend implementations.

Try the TLS and CONNECT examples

Two more runnable configs from examples/, showing mutual TLS and an HTTP forward proxy:

Independent frontend/backend TLS, including mutual TLS

[[servers]]
name = "secure"
protocol = "http"
listen = ":8443"

[servers.tls]
certificate_file = "certs/frontend.pem"
private_key_file = "certs/frontend-key.pem"
minimum_version = "1.3"

[[mounts]]
path = "/*"
target = "https://backend.internal/*"
server = "secure"
protocol = "http"

[mounts.tls]
ca_file = "certs/backend-ca.pem"
server_name = "backend.internal"
client_certificate_file = "certs/client.pem"
client_private_key_file = "certs/client-key.pem"
minimum_version = "1.2"

Authorized HTTP CONNECT as a bounded TCP relay

[[servers]]
name = "proxy"
protocol = "http"
listen = "127.0.0.1:8080"

[[mounts]]
source = "connect://origin.example:443/"
target = "tcp://127.0.0.1:9443"
server = "proxy"
protocol = "http"

[[policies]]
effect = "permit"
protocol = "http"
destination = "127.0.0.1"
source = "127.0.0.1"
method = "CONNECT"
mount = "connect://origin.example:443/"

Invariants worth knowing before you poke at it

  • Configuration is parsed and validated completely before activation; a failed reload leaves the previous configuration active.
  • A request cannot reach a connector without an affirmative policy decision — deny is the default, not an edge case.
  • The direct socket peer is authoritative unless it's an explicitly trusted proxy; malformed forwarded-client-address chains from trusted proxies fail closed.
  • Backend TLS verification cannot be disabled by configuration — there is no insecure-skip-verify knob.
  • Secret values never enter the canonical configuration or observability event model.
  • CONNECT relays have bounded dial, handshake, and idle deadlines; both hijacked connections close together when the relay ends.
